15:T46aa,<blockquote>
<p>人月聊IT讲的「本体」，不是传统 Semantic Web / OWL 课程里的 Ontology，而是借鉴 <strong>Palantir Ontology</strong> 的思想：先建一层描述「企业世界」的业务语义模型，再让 AI 基于它理解、推理、决策与执行。<br>
本文汇总其核心判断、M1～M7 + ME 体系，以及如何落到一个可开发的 <strong>Ontology-driven Agent Platform</strong>。</p>
</blockquote>
<hr>
<h2>一、先说结论</h2>
<p>一句话：</p>
<blockquote>
<p><strong>不要让 AI 直接从数据库和代码理解企业，而是先建立一层描述「企业世界」的本体模型，再让 AI 基于这个模型进行理解、推理、决策和执行。</strong></p>
</blockquote>
<p>核心链路：</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="text" data-theme="github-dark-dimmed"><code data-language="text" data-theme="github-dark-dimmed" style="display: grid;"><span data-line=""><span>真实业务世界</span></span>
<span data-line=""><span>      ↓</span></span>
<span data-line=""><span>业务需求</span></span>
<span data-line=""><span>      ↓</span></span>
<span data-line=""><span>Ontology 本体模型（M1～M7 + ME）</span></span>
<span data-line=""><span>      ↓</span></span>
<span data-line=""><span>本体运行平台 / Harness</span></span>
<span data-line=""><span>      ↓</span></span>
<span data-line=""><span>Skills / Tools</span></span>
<span data-line=""><span>      ↓</span></span>
<span data-line=""><span>Agent</span></span>
<span data-line=""><span>      ↓</span></span>
<span data-line=""><span>AI 原生应用 → 分析 / 决策 / 执行</span></span></code></pre></figure>
<p>这和传统 <code>数据库 → CRUD → 业务代码 → 页面</code> 完全不同。</p>
<p>相关视频如《本体论和本体建模-具体应用场景究竟是什么？》强调的也是：本体适合创新探索、分析推理、多目标权衡；规则清晰的问题应走精确代码。详见同栏目笔记：<a href="/wssf/notes/ai/%E6%9C%AC%E4%BD%93%E8%AE%BA%E5%BA%94%E7%94%A8%E5%9C%BA%E6%99%AF/">本体论和本体建模：具体应用场景究竟是什么？</a>。</p>
<hr>
<h2>二、别踩错路线：他讲的不是 OWL 入门课</h2>
<p>直接搜「Ontology 教程」，容易掉进：</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="text" data-theme="github-dark-dimmed"><code data-language="text" data-theme="github-dark-dimmed" style="display: grid;"><span data-line=""><span>哲学 → 形式逻辑 → RDF → RDFS → OWL → Description Logic → Semantic Web</span></span></code></pre></figure>
<p>这是正统 Ontology Engineering，但<strong>不是人月聊IT当前主线</strong>。</p>
<p>他实际更接近：</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="text" data-theme="github-dark-dimmed"><code data-language="text" data-theme="github-dark-dimmed" style="display: grid;"><span data-line=""><span>Enterprise Ontology</span></span>
<span data-line=""><span>+ Palantir Ontology</span></span>
<span data-line=""><span>+ DDD / Domain Modeling</span></span>
<span data-line=""><span>+ Enterprise Architecture</span></span>
<span data-line=""><span>+ Knowledge Graph</span></span>
<span data-line=""><span>+ AI Agent</span></span>
<span data-line=""><span>+ AI Native Application</span></span></code></pre></figure>
<p>想真正吃透这套视频：<strong>不要一上来啃 OWL</strong>。</p>
<p>三个常见误区：</p>

<p>层次可以记成：</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="text" data-theme="github-dark-dimmed"><code data-language="text" data-theme="github-dark-dimmed" style="display: grid;"><span data-line=""><span>Ontology   → 世界如何被理解</span></span>

<h2>三、体系总览：What / How / Why</h2>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="text" data-theme="github-dark-dimmed"><code data-language="text" data-theme="github-dark-dimmed" style="display: grid;"><span data-line=""><span>真实业务世界</span></span>
<span data-line=""><span>      ↓</span></span>
<span data-line=""><span>Ontology 本体</span></span>
<span data-line=""><span>      │</span></span>
<span data-line=""><span> ┌────┼────┐</span></span>
<span data-line=""><span> ↓    ↓    ↓</span></span>
<span data-line=""><span>What How  Why</span></span>
<span data-line=""><span>对象 行为  规则</span></span>
<span data-line=""><span> ↓    ↓    ↓</span></span>
<span data-line=""><span>Event / Scene → Process / Actor → Query / Analytics</span></span>
<span data-line=""><span>      ↓</span></span>
<span data-line=""><span>Skills / Tools → Agent → 分析 / 执行（改真实世界）</span></span></code></pre></figure>
<p>这也是他近期视频越来越集中到 <strong>Ontology → Harness → Agent → AI Native</strong> 的原因。</p>
<hr>
<h2>四、M1～M7 + ME（程序员版）</h2>
<p>截图与相关文章里的建模规范，可翻译成：</p>
<h3>M1 Object：企业里有什么</h3>
<p>业务世界对象，而非仅表结构。电商例：Customer / Product / Order / Payment / Warehouse / Supplier。</p>
<p>每个对象：属性、关联、生命周期。类似 Class / Struct / Table / DDD Entity，但语义锚定在<strong>业务世界</strong>。</p>
<h3>M2 Behavior：能做什么（关键）</h3>
<p>只有名词不够，Agent 需要动词：</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="text" data-theme="github-dark-dimmed"><code data-language="text" data-theme="github-dark-dimmed" style="display: grid;"><span data-line=""><span>Order → create / pay / cancel / refund / ship</span></span></code></pre></figure>
<p>从「AI 回答问题」变成「AI 操作业务世界」。Palantir 也强调 Ontology 除 objects/properties/links 外，还要有 actions/functions。</p>
<h3>M3 Rule：什么情况下允许做什么</h3>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="text" data-theme="github-dark-dimmed"><code data-language="text" data-theme="github-dark-dimmed" style="display: grid;"><span data-line=""><span>金额 > 10000 → 需经理审批</span></span>
<span data-line=""><span>status == PAID → 允许 Ship</span></span>
<span data-line=""><span>status == CANCELLED → 禁止 Ship</span></span></code></pre></figure>
<p>这是 Decision Intelligence 入口，也是「Agent 决策平台」该重点啃的一层。</p>
<h3>ME Event：什么时候发生了什么</h3>
<p>OrderCreated / PaymentCompleted / InventoryChanged …<br>
链路：<code>Object → Event → Behavior → Rule → Action</code>，非常接近 Agent Runtime。</p>
<h3>M4 Scenario：面对某类问题怎么办</h3>
<p>不是「有 Order 对象」，而是「客户投诉订单延迟时怎么办」——Actors、Objects、Events、Rules、Behaviors、Actions 组成<strong>任务上下文</strong>。</p>
<h3>M5 Actor：谁可以对什么做什么</h3>
<p>Customer / Employee / Manager / Supplier / AI Agent / System，天然带上权限、角色、责任边界。</p>
<h3>M6 Flow：事情怎么流转</h3>
<p>贷款审批、退款流程等；Agent 理解当前步骤、判断下一步、调 Skill 推进——Ontology → Workflow → Agent。</p>
<h3>M7 Query / Analytics：查、比、析、再决策</h3>
<p>Agent 不只执行动作，还要回答「过去 30 天销售额」「为何华东退货升高」「降价 5% 会怎样」——语义查询层隔离底层 SQL。</p>
<hr>
<h2>五、为什么像 Palantir</h2>
<p>Palantir 把 Ontology 放在企业数据与应用之间，并视为企业 <strong>digital twin</strong>：既有语义元素，也有动能元素；目标不是单纯描述数据，而是支撑复杂、互联的<strong>决策</strong>。</p>
<blockquote>
<p>值得研究的是 <strong>「Palantir Ontology 思想 + AI Agent」</strong>，而不只是传统 Ontology。</p>
</blockquote>
<p>视频学习可按五阶段：① 为什么需要本体 → ② Palantir（规则与行为核心）→ ③ M1～M7 + ME 精读 → ④ Ontology → AI Native → ⑤ Ontology + Harness + Agent。</p>
<hr>
<h2>六、项目定位：OpenOntology Agent</h2>
<p>不做一上来复刻 Palantir，先做：</p>
<blockquote>
<p><strong>用本体描述业务世界，用 Runtime 执行本体，用 Agent 消费本体。</strong></p>
</blockquote>
<p>目标形态：</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="text" data-theme="github-dark-dimmed"><code data-language="text" data-theme="github-dark-dimmed" style="display: grid;"><span data-line=""><span>自然语言 → 本体模型 → 对象/行为/规则/事件 → Agent → Tool/API → 真实业务系统</span></span></code></pre></figure>
<p>用户例：</p>
<blockquote>
<p>帮我分析最近销售额下降的原因；若华东库存不足，生成补货建议。</p>
</blockquote>
<p>Agent 不自由发挥，而是：读 Ontology → 找 Sales / Region / Inventory → Query → Rule → Decision → Action。</p>
<h3>六层架构</h3>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="text" data-theme="github-dark-dimmed"><code data-language="text" data-theme="github-dark-dimmed" style="display: grid;"><span data-line=""><span>AI Application（Chat / Copilot / Dashboard）</span></span>
<span data-line=""><span>        ↓</span></span>
<span data-line=""><span>Agent（Planner / Reasoner / Executor）</span></span>
<span data-line=""><span>        ↓</span></span>
<span data-line=""><span>Harness（Tool / Skill / Workflow / Event）</span></span>
<span data-line=""><span>        ↓</span></span>
<span data-line=""><span>Ontology Runtime（Object / Behavior / Rule / Query）</span></span>
<span data-line=""><span>        ↓</span></span>
<span data-line=""><span>Ontology Model（M1～M7 + ME）</span></span>
<span data-line=""><span>        ↓</span></span>
<span data-line=""><span>Data Layer（PostgreSQL / Redis / Vector / MQ）</span></span></code></pre></figure>
<p><strong>核心约束：Agent 不直连数据库，只走 Ontology Runtime。</strong></p>
<h3>Object 不能停在 ORM</h3>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="text" data-theme="github-dark-dimmed"><code data-language="text" data-theme="github-dark-dimmed" style="display: grid;"><span data-line=""><span>Order</span></span>
<span data-line=""><span>├── Properties / Links</span></span>
<span data-line=""><span>├── Behaviors / Rules</span></span>
<span data-line=""><span>├── Events / Actions</span></span></code></pre></figure>
<p>Behavior 形态：<code>Preconditions → Action → Effects → Event</code>。<br>
Rule 第一版可用简单表达式；MVP 不要上 Drools / DMN。<br>
Event + Trigger → Event-driven Agent。<br>
Actor + Permission → LLM 想做也得过本体权限。<br>
Query 提供语义能力名（如 <code>sales_by_region</code>），隔离 SQL。</p>
<h3>Harness / Skill / Tool</h3>
<ul>
<li><strong>Ontology</strong>：Agent 对业务世界的认知模型</li>
<li><strong>Harness</strong>：Agent 执行环境（Tool、Skill、Workflow、Memory、Permission、Event、Context）</li>
<li><strong>Tool</strong>：技术能力（如 <code>GET /orders/{id}</code>）</li>
<li><strong>Skill</strong>：业务能力（如 <code>refund_order</code>，可组合多个 Tool）</li>
</ul>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="text" data-theme="github-dark-dimmed"><code data-language="text" data-theme="github-dark-dimmed" style="display: grid;"><span data-line=""><span>API → Tool → Skill → Behavior → Agent</span></span></code></pre></figure>
<h3>竞争力不在「又一个 Agent」</h3>
<p>卖点不是聊天机器人，而是：</p>
<blockquote>
<p><strong>把企业业务世界建模成 AI 可理解、推理、执行的数字语义层。</strong></p>
</blockquote>
<p>从 AI 应用升级为 AI Infrastructure / Platform。</p>
<hr>
<h2>七、MVP：只做一个订单退款系统</h2>
<p>模型：<code>Customer → Order → Payment → Refund</code></p>
<p>Behavior：<code>Order.cancel</code> / <code>Refund.create|approve|execute</code></p>
<p>Rule：已支付 + 金额小于 1000 + 未退款 → 允许自动退款</p>
<p>对话：</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="text" data-theme="github-dark-dimmed"><code data-language="text" data-theme="github-dark-dimmed" style="display: grid;"><span data-line=""><span>「订单 10086 可以退款吗？」→ 查对象 → 评规则 → Decision</span></span>
<span data-line=""><span>「帮我退款。」→ 权限 → 规则 → create refund → Event</span></span></code></pre></figure>
<p>做到这里，就有一个真正的 Ontology + Agent MVP。</p>

<h2>八、学习路线（对齐「要做平台」而非「学知识图谱」）</h2>
<p>若目标只是知识图谱：<code>RDF / OWL / SPARQL / Neo4j / GraphRAG</code> 够用。</p>
<p>若目标是 <strong>Agent 决策平台 / AI 原生应用平台</strong>，建议：</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="text" data-theme="github-dark-dimmed"><code data-language="text" data-theme="github-dark-dimmed" style="display: grid;"><span data-line=""><span>企业架构 / 业务建模</span></span>
<span data-line=""><span>  → Ontology（Object + Behavior + Rule + Event）</span></span>
<span data-line=""><span>  → Scenario + Actor + Flow + Query</span></span>
<span data-line=""><span>  → Decision Model</span></span>
<span data-line=""><span>  → Skills → Harness → Agent → AI Native App</span></span></code></pre></figure>
<p>分 Level：业务建模（DDD、业务对象、流程、规则、事件）→ OWL 基础浅补 → Protégé 做电商本体 → KG + Neo4j/GraphRAG → Palantir 官方 Ontology 文档 → Ontology + Agent。</p>
