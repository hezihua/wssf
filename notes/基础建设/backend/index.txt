15:T2578,<h2>一、入口层（流量接入与治理）</h2>
<h3>1.1 客户端入口</h3>
<ul>
<li><strong>Web</strong>、<strong>iOS</strong>、<strong>安卓</strong>、<strong>PC</strong> 多端接入</li>
<li>流量来源区分：正常用户 vs <strong>Bot（机器人）</strong> vs <strong>第三方</strong> 调用</li>
</ul>
<h3>1.2 流量平台</h3>
<ul>
<li><strong>攻击清洗</strong>：防御 DDoS、恶意请求</li>
<li><strong>转发</strong>：流量分发到后端服务</li>
</ul>
<h3>1.3 网关层（Gateway）</h3>
<ul>
<li><strong>服务治理</strong>：统一入口管理</li>
<li><strong>监控 &#x26; 统计</strong>：实时流量、性能监控</li>
<li><strong>Cache</strong>：缓存加速，减轻后端压力</li>
<li>网关作为<strong>单一模块</strong>承接所有入口流量，再路由到后端服务</li>
</ul>
<hr>
<h2>二、资金层（钱）</h2>
<h3>2.1 支付对账平台</h3>
<ul>
<li>处理所有资金往来、交易流水对账</li>
</ul>
<h3>2.2 道具/抽奖/履约</h3>
<ul>
<li>虚拟道具发放</li>
<li>抽奖活动逻辑</li>
<li>订单履约闭环</li>
</ul>
<h3>2.3 支付渠道</h3>
<ul>
<li><strong>银行</strong>、<strong>微信支付（WX）</strong>、<strong>支付宝</strong></li>
<li>对接多渠道支付，保障资金通路稳定</li>
</ul>
<h3>2.4 To B 商家平台</h3>
<ul>
<li>面向商家的资金管理、结算、提现等功能</li>
<li>需防范 <strong>洗钱、羊毛党</strong> 等风险</li>
</ul>
<hr>
<h2>三、用户层</h2>
<h3>3.1 内部营销平台</h3>
<ul>
<li>用户增长、活动策划、营销推广</li>
<li>核心目标：<strong>增长 / 获客</strong></li>
</ul>
<h3>3.2 审核平台</h3>
<ul>
<li>内容/行为审核，保障平台合规</li>
<li>用户发布的内容、交易行为等都需要过审</li>
</ul>
<h3>3.3 用户数据报表</h3>
<ul>
<li><strong>BI 展示</strong>：业务数据可视化</li>
<li>支撑运营决策</li>
</ul>
<hr>
<h2>四、数据层</h2>
<h3>4.1 数据平台</h3>
<ul>
<li>提交 SQL、报表需求</li>
<li>支撑业务数据查询与分析</li>
</ul>
<h3>4.2 安全</h3>
<ul>
<li>数据安全策略、权限管控</li>
<li>敏感数据加密、防泄漏</li>
</ul>
<h3>4.3 存储基础设施</h3>
<table>

<tr>
<th>组件</th>
<th>用途</th>
</tr>

</tr>
<tr>
<td><strong>RDS</strong></td>
<td>关系型数据库，结构化数据存储</td>
</tr>
<tr>
<td><strong>ADB</strong></td>
<td>分析型数据库，大数据计算</td>
</tr>

<h3>4.4 监控要求</h3>
<blockquote>
<p>"这些平台都是要监控好的" —— 所有基础设施和业务平台都需要完善的监控告警体系，保障稳定性。</p>
</blockquote>
<hr>
<h2>五、风控层</h2>
<h3>5.1 安全审核</h3>
<ul>
<li><strong>资料变更</strong>：身份证号、手机号等敏感信息变更监控</li>
<li><strong>资金来往</strong>：交易行为风控</li>
<li><strong>消息识别</strong>：区分 <strong>机 / 人</strong>，识别异常消息（Bot 行为）</li>
<li>支持 <strong>人工审核</strong> 介入</li>
</ul>
<hr>
<h2>六、多媒体层</h2>
<h3>6.1 WebRTC</h3>
<ul>
<li><strong>语音、视频</strong> 实时通信</li>
<li><strong>信令</strong> 服务：连接建立、状态同步</li>
<li>属于<strong>底层</strong>能力，一般不展开细讲</li>
</ul>
<hr>

<h3>7.2 操作系统</h3>
<ul>
<li><strong>iOS</strong>、<strong>Windows</strong>、<strong>Linux</strong></li>
</ul>
<h3>7.3 基础设施</h3>
<ul>
<li><strong>告警 &#x26; 监控</strong>：全链路可观测性</li>
<li><strong>ECS</strong>：云服务器</li>
<li><strong>机房</strong>：物理服务器托管</li>
<li><strong>K8s</strong>：容器编排，现代化部署方式</li>
<li><strong>域名</strong>：DNS 管理</li>
</ul>
<h3>7.4 运维关注点</h3>
<ul>
<li><strong>SQL</strong>：数据库性能、慢查询优化</li>
<li><strong>高可用</strong>：服务容灾、故障自动切换</li>
<li><strong>内存、CPU、网络</strong>：核心资源监控</li>
</ul>
<hr>
<h2>八、后端固定组件选型</h2>
<blockquote>
<p>这些是后端开发中<strong>相对固定</strong>的几类组件，技术选型围绕它们展开：</p>
</blockquote>
<h3>8.1 语言</h3>
<ul>
<li>选型相对<strong>灵活</strong>，根据团队技术栈和场景选择</li>
</ul>
<h3>8.2 网络框架</h3>
<ul>
<li>需完成<strong>交流</strong>（通信）</li>
<li>明确<strong>哪一层</strong>、使用<strong>什么协议</strong></li>
<li>区分 <strong>关系型 / 非关系型</strong> 数据库</li>
<li>区分 <strong>分析型 / 事务型</strong> 场景</li>
<li>关注 <strong>内存 / 外存</strong> 使用</li>
</ul>
<h3>8.3 数据库</h3>
<ul>
<li>关系型：MySQL、PostgreSQL 等</li>
<li>非关系型：Redis、MongoDB 等</li>
</ul>
<h3>8.4 异步执行</h3>
<ul>
<li>完成<strong>异步执行</strong>任务</li>
<li><strong>定时 / 延时</strong> 任务调度</li>
</ul>
<h3>8.5 消息队列</h3>
<ul>
<li><strong>MQ</strong>（通用消息队列）</li>
<li><strong>Kafka</strong>：高吞吐日志/事件流处理</li>
</ul>
<h3>8.6 对象存储</h3>
<ul>
<li>静态资源、文件存储</li>
</ul>
<h3>8.7 支付底座</h3>
<ul>
<li>支付核心能力封装，供业务层调用</li>
</ul>
<h3>8.8 流量网关</h3>
<ul>
<li><strong>灰度</strong>：灰度发布，渐进式上线</li>
<li><strong>开关</strong>：功能开关（Feature Toggle），快速回滚/启用功能</li>
</ul>

<h2>十、核心设计要点总结</h2>
<ol>
<li><strong>入口统一</strong>：网关作为单一模块收口所有流量，便于治理和监控</li>
<li><strong>风险防控</strong>：资金层重点防范洗钱、羊毛；流量层防御攻击；风控层识别机/人</li>
<li><strong>数据驱动</strong>：BI 报表支撑业务决策，数据平台提供查询能力</li>
<li><strong>监控全覆盖</strong>：从基础设施到业务平台，监控告警不可或缺</li>
<li><strong>灰度与开关</strong>：流量网关支持灰度发布和功能开关，保障发布安全</li>
<li><strong>组件选型灵活</strong>：语言、框架相对灵活，但消息队列、存储、网关等组件类型相对固定</li>
