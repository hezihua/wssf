<h2>概述</h2>
<h3>什么是 Passkey？</h3>
<p><strong>Passkey</strong> 是基于 FIDO2/WebAuthn 标准的无密码认证技术，使用公钥加密和生物识别（指纹、人脸、PIN）来替代传统密码。</p>
<h3>核心优势</h3>
<ul>
<li>✅ <strong>无密码</strong>：无需记忆复杂密码</li>
<li>✅ <strong>更安全</strong>：私钥永不离开设备，无法被窃取</li>
<li>✅ <strong>便捷</strong>：支持无用户名登录（可发现凭证）</li>
<li>✅ <strong>跨平台</strong>：支持电脑、手机、USB 密钥等多种设备</li>
</ul>
<h3>技术栈</h3>
<ul>
<li><strong>前端</strong>: Next.js 14 (App Router), React, Ant Design</li>
<li><strong>后端</strong>: Next.js API Routes</li>
<li><strong>Passkey 库</strong>: <code>@simplewebauthn/server</code>, <code>@simplewebauthn/browser</code></li>
<li><strong>存储</strong>: 文件存储（生产环境应使用数据库）</li>
</ul>
<hr>
<h2>FIDO2 与 WebAuthn 标准</h2>
<h3>FIDO2 组成</h3>
<p><strong>FIDO2</strong> 由两个核心规范组成：</p>
<ol>
<li>
<p><strong>WebAuthn (Web Authentication API)</strong> - W3C 标准</p>
<ul>
<li>浏览器端的 JavaScript API</li>
<li>定义如何与认证器交互</li>
<li>由浏览器厂商实现</li>
</ul>
</li>
<li>
<p><strong>CTAP2 (Client to Authenticator Protocol 2)</strong> - FIDO Alliance 标准</p>
<ul>
<li>定义客户端与认证器之间的通信协议</li>
<li>支持 USB、NFC、BLE 等传输方式</li>
<li>由认证器厂商实现</li>
</ul>
</li>
</ol>
<h3>架构图</h3>
<pre><code>┌─────────────┐
│   Web 应用  │
└──────┬──────┘
       │ WebAuthn API
       │ (navigator.credentials)
       ▼
┌─────────────┐
│   浏览器    │
└──────┬──────┘
       │ CTAP2 协议
       │ (USB/NFC/BLE)
       ▼
┌─────────────┐
│   认证器    │
│ (Passkey)   │
└─────────────┘
</code></pre>
<h3>标准符合性</h3>
<p>当前实现<strong>完全符合 FIDO2 标准</strong>：</p>
<ul>
<li>✅ 使用标准 WebAuthn API</li>
<li>✅ 使用标准服务端验证库</li>
<li>✅ 实现可发现凭证（FIDO2 Level 2）</li>
<li>✅ 符合所有安全要求</li>
<li>✅ 支持多种算法和传输方式</li>
</ul>

<h3>流程图</h3>
<h4>注册流程</h4>
<pre><code>用户填写信息
    ↓
POST /register/challenge
    ↓ 返回 challenge
navigator.credentials.create()
    ↓ 用户验证，生成密钥对
POST /register/verify
    ↓ 验证签名，提取公钥
保存凭证到文件
    ↓
注册完成
</code></pre>
<h4>登录流程</h4>
<pre><code>用户点击登录
    ↓
POST /challenge
    ↓ 返回 challenge
navigator.credentials.get()
    ↓ 用户选择并验证，使用私钥签名
POST /verify
    ↓ 验证签名，检查计数器
更新计数器，生成 token
    ↓
登录完成
</code></pre>

<h2>实现问题总结</h2>
<h3>问题 1: 路由 404 错误</h3>
<p><strong>问题描述：</strong></p>
<pre><code>POST http://localhost:3008/api/auth/passkey/verify 404 (Not Found)
</code></pre>
<p><strong>原因分析：</strong></p>
<ul>
<li>找不到对应的 passkey 凭证</li>
<li>服务器日志显示：<code>存储的所有凭证数量: 0</code></li>
</ul>
<p><strong>解决方案：</strong></p>
<ol>
<li>确认路由存在：使用 <code>curl</code> 测试接口</li>
<li>检查凭证存储：发现存储被清空（服务器重启导致）</li>
<li>重新注册：需要先注册 Passkey，然后再登录</li>
</ol>
<h3>问题 2: userHandle 编码问题</h3>
<p><strong>问题描述：</strong>
服务器端从 <code>userHandle</code> 解码得到的是 base64 编码的字符串，而不是原始字符串。</p>
<p><strong>原因分析：</strong></p>
<ol>
<li>注册时：<code>user-zhe</code> → UTF-8 字节数组 → base64url 编码 → 传给 WebAuthn API</li>
<li>登录时：WebAuthn 返回 <code>userHandle</code> (ArrayBuffer) → 前端转换为 base64url 字符串 → 服务器端解码</li>
</ol>
<p><strong>解决方案：</strong></p>
<ul>
<li>服务器端：简化解码逻辑，直接解码 base64url 字符串</li>
<li>前端：正确解码 userHandle</li>
</ul>
<h3>问题 3: userId 不一致问题</h3>
<p><strong>问题描述：</strong>
注册时生成的 <code>userId</code> 与登录时从 <code>userHandle</code> 获取的 <code>userId</code> 不一致，导致找不到凭证。</p>
<p><strong>原因分析：</strong>
注册时使用了时间戳：</p>

<h3>问题 4: 凭证存储被清空</h3>

<h2>安全机制</h2>
<h3>1. 防重放攻击</h3>
<ul>
<li><strong>Challenge</strong>：每次请求生成新的随机 challenge</li>
<li><strong>Counter</strong>：每次使用后递增，防止重复使用</li>
<li><strong>时效性</strong>：Challenge 通常有时效性（如 60 秒）</li>
</ul>
<h3>2. 域名验证</h3>
<ul>
<li><strong>Origin</strong>：验证请求来源</li>
<li><strong>RP ID</strong>：验证依赖方ID（域名）</li>
</ul>
<h3>3. 用户验证</h3>
<ul>
<li><strong>User Verification</strong>：要求用户验证（指纹/人脸/PIN）</li>
<li><strong>防止</strong>：设备被盗用</li>
</ul>
<h3>4. 签名验证</h3>
<ul>
<li><strong>私钥</strong>：永远不离开设备</li>
<li><strong>公钥</strong>：存储在服务端，用于验证签名</li>
</ul>
<h3>5. 防克隆攻击</h3>
<ul>
<li><strong>计数器</strong>：每次认证后，签名计数器递增</li>
<li><strong>验证</strong>：服务器检查计数器是否递增</li>
<li><strong>检测</strong>：如果计数器 ≤ 已保存的值 → 可能是克隆凭证</li>
</ul>
<h3>安全模型</h3>
<pre><code>注册时：
  认证器生成密钥对（私钥 + 公钥）
  私钥 → 永远留在设备本地（永不传输）
  公钥 → 发送给服务器保存

登录时：
  服务器发送 challenge
  认证器用私钥签名 challenge
  服务器用公钥验证签名
</code></pre>

<h2>关键概念</h2>
<h3>1. Challenge（挑战）</h3>
<ul>
<li><strong>作用</strong>：防重放攻击</li>
<li><strong>生成</strong>：服务端生成随机字符串</li>
<li><strong>验证</strong>：确保响应是针对当前请求的</li>
</ul>
<h3>2. User ID（用户标识）</h3>
<ul>
<li><strong>注册时</strong>：服务端生成唯一ID，传入 <code>user.id</code></li>
<li><strong>存储位置</strong>：认证器设备本地（可发现凭证）</li>
<li><strong>登录时</strong>：从 <code>userHandle</code> 中获取</li>
</ul>
<h3>3. Resident Key（可发现凭证）</h3>
<ul>
<li><strong>特点</strong>：用户信息存储在设备本地</li>
<li><strong>优势</strong>：登录时无需输入用户名</li>
<li><strong>设置</strong>：<code>requireResidentKey: true</code></li>
</ul>
<h3>4. AllowCredentials（允许的凭证）</h3>
<ul>
<li><strong>提供时</strong>：限制只能使用指定的凭证</li>
<li><strong>不提供时</strong>：浏览器枚举所有可发现凭证（无用户名登录）</li>
</ul>
<h3>5. Counter（计数器）</h3>
<ul>
<li><strong>作用</strong>：防止重放攻击</li>
<li><strong>规则</strong>：每次使用后必须递增</li>
<li><strong>验证</strong>：服务端检查 counter 是否大于上次的值</li>
</ul>
<h3>6. Signature（签名）</h3>
<ul>
<li><strong>生成</strong>：使用私钥对 <code>challenge + authenticatorData</code> 签名</li>
<li><strong>验证</strong>：使用公钥验证签名，证明拥有私钥</li>
</ul>
