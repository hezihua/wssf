15:T2f6e,<p>以 <a href="https://github.com/huangruiteng/loopx/pull/2763">LoopX #2763</a> 为例，说明没有上游写权限时，如何把本地改动合进原项目。</p>
<p>对应 issue：<a href="https://github.com/huangruiteng/loopx/issues/2761">#2761</a></p>
<hr>
<h2>一、原理</h2>
<p>贡献者通常不能直接 <code>push</code> 到原仓库（上游）。协作靠三份拷贝：</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="text" data-theme="github-dark-dimmed"><code data-language="text" data-theme="github-dark-dimmed" style="display: grid;"><span data-line=""><span>上游（upstream）</span></span>
<span data-line=""><span>  huangruiteng/loopx     ← 原项目主干</span></span>
<span data-line=""><span>        ▲</span></span>
<span data-line=""><span>        │  Pull Request（申请合并）</span></span>
<span data-line=""><span>        │</span></span>
<span data-line=""><span>你的 fork</span></span>
<span data-line=""><span>  hezihua/loopx          ← 你有写权限的 GitHub 副本</span></span>
<span data-line=""><span>        ▲</span></span>
<span data-line=""><span>        │  git push</span></span>
<span data-line=""><span>        │</span></span>
<span data-line=""><span>本地工作区</span></span>
<span data-line=""><span>  改文件、commit 的地方</span></span></code></pre></figure>
<table>
<thead>
<tr>
<th>位置</th>
<th>作用</th>
</tr>
</thead>
<tbody>
<tr>
<td>本地</td>
<td>编辑、验证、commit</td>
</tr>
<tr>
<td>Fork</td>
<td>你能 push 的远程</td>
</tr>
<tr>
<td>上游</td>
<td>真正要合入的目标；通过 PR 申请</td>
</tr>
</tbody>
</table>
<p>直接推上游若出现 <code>Permission denied</code>，属于正常情况，应改为推 fork 再开 PR。</p>
<p><strong>开 PR ≠ 已合并。</strong> PR 是审查申请；合并由有权限的 maintainer 完成。</p>
<hr>
<h2>二、本次实际做了什么（#2763）</h2>
<ol>
<li><strong>选切口</strong>：修架构文档与代码不一致（七层 / 六动词词表 vs 真实 Turn 枚举），纯文档、范围小。</li>
<li><strong>干净分支</strong>：从 <code>origin/main</code> 建 worktree 与分支<br>
<code>codex/align-architecture-docs-inventory-2761</code>。</li>
<li><strong>改文件</strong>：
<ul>
<li><code>docs/architecture.md</code>：六层 durable surface；<code>next_probe</code>/pre-tick 标为 optional；补充 Turn Decision Vocabulary（<code>LoopXTurnRoute</code> / <code>LoopXTurnResultKind</code>）。</li>
<li>若干 control-plane course 入口：避免把六动词写成唯一协议词表。</li>
</ul>
</li>
<li><strong>验证</strong>：<code>loopx check</code>（public boundary）+ <code>git diff --check</code>。</li>
<li><strong>Commit</strong>：说明 why，并用 <code>Fixes #2761</code> / <code>Closes #2761</code> 关联 issue。</li>
<li><strong>Push fork</strong>：<code>git push -u fork HEAD</code>（推上游会 403）。</li>
<li><strong>开 PR</strong>：head = <code>hezihua:codex/...</code>，base = <code>huangruiteng:main</code> → <a href="https://github.com/huangruiteng/loopx/pull/2763">#2763</a>。</li>
</ol>
<hr>
<h2>三、怎么开 PR</h2>
<p>网页和 <code>gh</code> <strong>二选一</strong>即可，效果相同：都是向上游开一条 PR。任选一种完成即可，不必两种都做。</p>
<h3>3.1 网页</h3>
<ol>
<li>本地 commit 后推到 fork：
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="bash" data-theme="github-dark-dimmed"><code data-language="bash" data-theme="github-dark-dimmed" style="display: grid;"><span data-line=""><span style="color:#F69D50">git</span><span style="color:#96D0FF"> remote</span><span style="color:#96D0FF"> add</span><span style="color:#96D0FF"> fork</span><span style="color:#96D0FF"> https://github.com/</span><span style="color:#F47067">&#x3C;</span><span style="color:#96D0FF">用户</span><span style="color:#ADBAC7">名</span><span style="color:#F47067">></span><span style="color:#96D0FF">/loopx.git</span><span style="color:#768390">   # 仅首次</span></span>
<span data-line=""><span style="color:#F69D50">git</span><span style="color:#96D0FF"> push</span><span style="color:#6CB6FF"> -u</span><span style="color:#96D0FF"> fork</span><span style="color:#96D0FF"> HEAD</span></span></code></pre></figure>
</li>
<li>打开 compare 链接（或 fork 页的 <strong>Compare &#x26; pull request</strong>）：
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="text" data-theme="github-dark-dimmed"><code data-language="text" data-theme="github-dark-dimmed" style="display: grid;"><span data-line=""><span>https://github.com/huangruiteng/loopx/compare/main...&#x3C;用户名>:loopx:&#x3C;分支名>?expand=1</span></span></code></pre></figure>
</li>
<li>确认：
<ul>
<li><strong>base</strong>：<code>huangruiteng/loopx</code> 的 <code>main</code></li>
<li><strong>compare</strong>：你的 fork 分支</li>
</ul>
</li>
<li>填写标题与正文后点 <strong>Create pull request</strong>。</li>
</ol>
<h3>3.2 命令行</h3>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="bash" data-theme="github-dark-dimmed"><code data-language="bash" data-theme="github-dark-dimmed" style="display: grid;"><span data-line=""><span style="color:#F69D50">gh</span><span style="color:#96D0FF"> pr</span><span style="color:#96D0FF"> create</span><span style="color:#F47067"> \</span></span>
<span data-line=""><span style="color:#6CB6FF">  --repo</span><span style="color:#96D0FF"> huangruiteng/loopx</span><span style="color:#F47067"> \</span></span>
<span data-line=""><span style="color:#6CB6FF">  --head</span><span style="color:#F47067"> &#x3C;</span><span style="color:#96D0FF">用户</span><span style="color:#ADBAC7">名</span><span style="color:#F47067">></span><span style="color:#96D0FF">:</span><span style="color:#F47067">&#x3C;</span><span style="color:#96D0FF">分支</span><span style="color:#ADBAC7">名</span><span style="color:#F47067">></span><span style="color:#F47067"> \</span></span>
<span data-line=""><span style="color:#6CB6FF">  --base</span><span style="color:#96D0FF"> main</span><span style="color:#F47067"> \</span></span>
<span data-line=""><span style="color:#6CB6FF">  --title</span><span style="color:#96D0FF"> "简短标题"</span><span style="color:#F47067"> \</span></span>
<span data-line=""><span style="color:#6CB6FF">  --body</span><span style="color:#96D0FF"> "$(</span><span style="color:#F69D50">cat</span><span style="color:#F47067"> &#x3C;&#x3C;</span><span style="color:#96D0FF">'EOF'</span></span>
<span data-line=""><span style="color:#96D0FF">## Summary</span></span>
<span data-line=""><span style="color:#96D0FF">- 改了什么、为什么</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#96D0FF">Fixes #&#x3C;issue号></span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#96D0FF">## Test plan</span></span>
<span data-line=""><span style="color:#96D0FF">- [ ] 跑了哪些检查</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#96D0FF">EOF</span></span>
<span data-line=""><span style="color:#96D0FF">)"</span></span></code></pre></figure>
<p>需要先 <code>gh auth login</code>（或可用 token）。</p>
<h3>3.3 PR 正文建议包含</h3>
<ul>
<li><strong>Summary</strong>：改了什么、对应哪个 issue</li>
<li><strong>Test plan</strong>：验证命令与结果</li>
<li>用 <code>Fixes #N</code> 便于合并后自动关 issue</li>
</ul>
<hr>
<h2>四、开完之后</h2>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="text" data-theme="github-dark-dimmed"><code data-language="text" data-theme="github-dark-dimmed" style="display: grid;"><span data-line=""><span>PR Open → CI / Review →（同分支继续改并 push）→ Maintainer Merge → 进入上游 main</span></span></code></pre></figure>
<ul>
<li>Review 要改代码：在<strong>同一分支</strong>继续 commit，再 <code>git push fork HEAD</code>；PR 会自动更新。</li>
<li>合并后可选同步自己的 fork <code>main</code>：
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="bash" data-theme="github-dark-dimmed"><code data-language="bash" data-theme="github-dark-dimmed" style="display: grid;"><span data-line=""><span style="color:#F69D50">git</span><span style="color:#96D0FF"> fetch</span><span style="color:#96D0FF"> origin</span></span>
<span data-line=""><span style="color:#F69D50">git</span><span style="color:#96D0FF"> checkout</span><span style="color:#96D0FF"> main</span></span>
<span data-line=""><span style="color:#F69D50">git</span><span style="color:#96D0FF"> merge</span><span style="color:#96D0FF"> origin/main</span></span>
<span data-line=""><span style="color:#F69D50">git</span><span style="color:#96D0FF"> push</span><span style="color:#96D0FF"> fork</span><span style="color:#96D0FF"> main</span></span></code></pre></figure>
</li>
</ul>

<h2>六、注意</h2>
<ul>
<li>PR 必须开向<strong>上游仓库</strong>，不是只在 fork 里合到自己的 <code>main</code>。</li>
<li>一个 PR 一个主题；文档 / 行为 / 大重构尽量拆开。</li>
<li>不要提交私有状态、本机绝对路径、credentials；LoopX 可用 <code>loopx check</code> 扫边界。</li>
<li>没有上游写权限时，合并只能等 maintainer。</li>
</ul>
