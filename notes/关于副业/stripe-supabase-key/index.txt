<h2>🔑 密钥获取方法</h2>
<h3>1. Supabase 密钥</h3>
<h4>步骤 1：登录 Supabase Dashboard</h4>
<p>访问：<a href="https://supabase.com/dashboard">https://supabase.com/dashboard</a></p>
<h4>步骤 2：选择项目</h4>
<p>选择你的项目或创建新项目</p>
<h4>步骤 3：获取 API 密钥</h4>
<ol>
<li>点击左侧菜单 <strong>Settings</strong>（设置）</li>
<li>选择 <strong>API key</strong> 子菜单</li>
<li>在 <strong>Publishable and secret API keys</strong> 部分找到以下信息：
<strong>获取的密钥：</strong></li>
</ol>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="bash" data-theme="github-dark-dimmed"><code data-language="bash" data-theme="github-dark-dimmed" style="display: grid;"><span data-line=""><span style="color:#768390"># anon public (公开密钥)</span></span>
<span data-line=""><span style="color:#ADBAC7">NEXT_PUBLIC_SUPABASE_ANON_KEY</span><span style="color:#F47067">=</span><span style="color:#96D0FF">eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#768390"># service_role (服务端密钥) ⚠️ 敏感信息</span></span>
<span data-line=""><span style="color:#ADBAC7">SUPABASE_SERVICE_ROLE_KEY</span><span style="color:#F47067">=</span><span style="color:#96D0FF">eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...</span></span></code></pre></figure>
<ol>
<li>点击左侧菜单 <strong>Settings</strong>（设置）</li>
<li>选择 <strong>data API</strong> 子菜单</li>
<li>在 <strong>Project URL</strong> 部分找到以下信息：
<strong>获取的密钥：</strong></li>
</ol>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="bash" data-theme="github-dark-dimmed"><code data-language="bash" data-theme="github-dark-dimmed" style="display: grid;"><span data-line=""> </span>
<span data-line=""><span style="color:#768390"># Project URL</span></span>
<span data-line=""><span style="color:#ADBAC7">NEXT_PUBLIC_SUPABASE_URL</span><span style="color:#F47067">=</span><span style="color:#96D0FF">https://your-project.supabase.co</span></span></code></pre></figure>
<p><strong>注意事项：</strong></p>
<ul>
<li>⚠️ <code>SUPABASE_SERVICE_ROLE_KEY</code> 拥有超级管理员权限，绕过所有 RLS 策略</li>
<li>⚠️ 永远不要在客户端代码中使用 <code>SERVICE_ROLE_KEY</code></li>
<li>⚠️ 不要提交到 Git 仓库</li>
</ul>
<h4>步骤 4：配置 OAuth 重定向 URL（如果使用 OAuth 登录）</h4>
<ol>
<li>左侧菜单：<strong>Authentication</strong> → <strong>URL Configuration</strong></li>
<li>在 <strong>Redirect URLs</strong> 中添加：
<pre><code>http://localhost:3000/**
https://your-domain.com/**
https://*.vercel.app/**
</code></pre>
</li>
<li>设置 <strong>Site URL</strong>：
<pre><code>https://your-domain.com
</code></pre>
</li>
<li>点击 <strong>Save</strong></li>
</ol>
<hr>
<h3>2. Stripe 密钥</h3>
<h4>步骤 1：登录 Stripe Dashboard</h4>
<p>访问：<a href="https://dashboard.stripe.com">https://dashboard.stripe.com</a></p>
<h4>步骤 2：创建账户</h4>
<p>如果没有账户，先注册并完成账户设置</p>
<h4>步骤 3：获取 API 密钥</h4>
<ol>
<li>点击左侧菜单 <strong>Developers</strong>（开发者）</li>
<li>选择 <strong>API keys</strong>（API 密钥）</li>
</ol>
<h4>步骤 4：选择环境</h4>
<p>Stripe 提供两种环境：</p>
<p><strong>测试环境（Test mode）：</strong></p>
<ul>
<li>用于开发和测试</li>
<li>不会产生真实交易</li>
<li>密钥以 <code>pk_test_</code> 和 <code>sk_test_</code> 开头</li>
</ul>
<p><strong>生产环境（Live mode）：</strong></p>
<ul>
<li>用于正式上线</li>
<li>会产生真实交易</li>
<li>密钥以 <code>pk_live_</code> 和 <code>sk_live_</code> 开头</li>
<li>需要完成账户激活流程</li>
</ul>
<h4>步骤 5：复制密钥</h4>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="bash" data-theme="github-dark-dimmed"><code data-language="bash" data-theme="github-dark-dimmed" style="display: grid;"><span data-line=""><span style="color:#768390"># Publishable key (公开密钥)</span></span>
<span data-line=""><span style="color:#ADBAC7">NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY</span><span style="color:#F47067">=</span><span style="color:#96D0FF">pk_test_51xxx...</span></span>
<span data-line=""><span style="color:#768390"># 或生产环境</span></span>
<span data-line=""><span style="color:#ADBAC7">NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY</span><span style="color:#F47067">=</span><span style="color:#96D0FF">pk_live_51xxx...</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:#768390"># Secret key (密钥) ⚠️ 敏感信息</span></span>
<span data-line=""><span style="color:#ADBAC7">STRIPE_SECRET_KEY</span><span style="color:#F47067">=</span><span style="color:#96D0FF">sk_test_51xxx...</span></span>
<span data-line=""><span style="color:#768390"># 或生产环境</span></span>
<span data-line=""><span style="color:#ADBAC7">STRIPE_SECRET_KEY</span><span style="color:#F47067">=</span><span style="color:#96D0FF">sk_live_51xxx...</span></span></code></pre></figure>
<p><strong>注意事项：</strong></p>
<ul>
<li>✅ 开发阶段使用测试密钥（<code>test</code>）</li>
<li>✅ 生产环境使用生产密钥（<code>live</code>）</li>
<li>⚠️ <code>Secret key</code> 只能在服务端使用</li>
<li>⚠️ 切换到生产环境前需要激活 Stripe 账户</li>
</ul>

<h2>🔒 安全最佳实践</h2>
<h3>1. 保护敏感信息</h3>
<p><strong>永远不要提交到 Git：</strong></p>
<ul>
<li><code>.env.local</code> - 已在 <code>.gitignore</code> 中</li>
<li>任何包含真实密钥的文件</li>
</ul>
<p><strong>可以提交的文件：</strong></p>
<ul>
<li><code>.env.example</code> - 只包含占位符</li>
<li><code>.env.production</code> - 只包含占位符</li>
</ul>
<h3>2. 密钥权限分级</h3>
<table>
<thead>
<tr>
<th>密钥类型</th>
<th>使用位置</th>
<th>权限级别</th>
</tr>
</thead>
<tbody>
<tr>
<td><code>NEXT_PUBLIC_*</code></td>
<td>客户端 + 服务端</td>
<td>公开</td>
</tr>
<tr>
<td><code>SUPABASE_SERVICE_ROLE_KEY</code></td>
<td>仅服务端</td>
<td>超级管理员 ⚠️</td>
</tr>
<tr>
<td><code>STRIPE_SECRET_KEY</code></td>
<td>仅服务端</td>
<td>管理员 ⚠️</td>
</tr>
</tbody>
</table>
<h3>3. 定期轮换密钥</h3>
<ul>
<li>✅ 定期更新生产环境密钥</li>
<li>✅ 如果怀疑密钥泄露，立即重新生成</li>
<li>✅ 使用环境变量而不是硬编码</li>
</ul>
<h3>4. 测试与生产隔离</h3>
<ul>
<li>✅ 本地开发使用测试密钥</li>
<li>✅ 生产环境使用生产密钥</li>
<li>✅ 不要在生产环境使用测试密钥</li>
</ul>

<h2>❓ 常见问题</h2>
<h3>Q: 本地可以登录，部署后不行？</h3>
<p><strong>A:</strong> 检查 Supabase 的 OAuth 重定向 URL 配置，需要添加生产域名。</p>
<h3>Q: Stripe 支付失败？</h3>
<p><strong>A:</strong> 确认使用了正确环境的密钥（测试/生产），检查密钥是否有效。</p>
<h3>Q: 环境变量修改后没有生效？</h3>
<p><strong>A:</strong> Vercel 需要重新部署才能应用新的环境变量，点击 Redeploy。</p>
<h3>Q: 如何区分测试和生产环境？</h3>
<p><strong>A:</strong> 使用 <code>NEXT_PUBLIC_SANDBOX</code> 变量，本地设为 <code>true</code>，生产设为 <code>false</code>。</p>
