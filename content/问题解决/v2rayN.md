# v2rayN 下载与使用实践指南

> 本文档适用于 v2rayN V7.x 版本，Windows 平台。

## 一、下载安装

### 1.1 下载 v2rayN

访问 GitHub Releases 页面下载最新版：

🔗 [https://github.com/2dust/v2rayN/releases](https://github.com/2dust/v2rayN/releases)

选择带有 `windows-64-With-Core` 后缀的压缩包，例如：

```
v2rayN-With-Core.zip
```

**提示：** With-Core 版本内置了 Xray 核心，下载后可直接使用，无需额外配置。

### 1.2 解压运行

1. 将下载的压缩包解压到任意文件夹（建议放在非系统盘，如 `D:\v2rayN`）
2. 进入解压后的文件夹，双击运行 `v2rayN.exe`
3. 首次运行可能会提示 Windows 安全警告，点击 **「更多信息」 → 「仍要运行」**

**注意：** v2rayN 不需要安装，解压即用。建议右键 `v2rayN.exe` → **「发送到」 → 「桌面快捷方式」**，方便下次启动。

## 二、添加订阅

### 2.1 打开订阅分组设置

启动 v2rayN 后，点击顶部菜单栏的 **「订阅分组」** → 选择 **「订阅分组设置」**。

### 2.2 添加订阅链接

在弹出的「订阅分组设置」窗口中：

1. 点击 **「添加」** 按钮
2. 填写以下信息：
   - **别名：** 自定义一个名称，例如 `JMS`
   - **可选地址 (Url)：** 粘贴你的订阅链接
   - **启用更新：** 勾选 ✓
   - **自动更新间隔：** 建议设为 `60`（分钟），留 `0` 表示不自动更新
3. 点击 **「确认」** 保存

### 2.3 关闭设置窗口

点击右上角的 **「关闭」** 或 × 按钮，回到主界面。

## 三、更新订阅获取节点

回到主界面后，获取服务器节点：

1. 点击顶部菜单 **「订阅分组」**
2. 选择 **「更新全部订阅（不通过代理）」**
3. 或者点击主界面上方工具栏的 🔄 刷新图标

等待片刻，主界面中间的列表区域会出现节点信息，包含：

- 类型（Shadowsocks / VLESS / VMess 等）
- 别名
- 地址
- 端口
- 传输协议
- TLS
- 延迟

## 四、选择节点

在节点列表中，**右键点击** 你想使用的节点 → 选择 **「设为活动服务器」**。

**建议：** 优先选择 VLESS 类型的节点，相比 Shadowsocks 更安全、更稳定。

## 五、开启系统代理

### 5.1 设置代理模式

看窗口右下角的代理状态按钮：

1. 点击当前显示的文字（如 **「清除系统代理」**）
2. 在弹出的菜单中选择 **「自动配置系统代理」**

### 5.2 验证代理是否生效

打开浏览器，访问以下网站测试：

- [https://www.google.com](https://www.google.com)
- [https://www.youtube.com](https://www.youtube.com)

如果能正常打开，说明代理配置成功！

## 六、Git 代理配置（命令行工具）

v2rayN 开启「自动配置系统代理」后，浏览器等应用会自动走代理，但 Git 等命令行工具不会自动跟随系统代理，需要单独配置。

### 6.1 v2rayN 端口说明

| 协议 | 端口 | 适用场景 |
| --- | --- | --- |
| SOCKS5 | 10808 | Git、命令行工具、部分应用 |
| HTTP | 10809 | 浏览器、部分应用 |

可在 v2rayN 左下角看到实际端口：`本地:[mixed:10808]`

### 6.2 配置 Git 走代理

打开终端（PowerShell / Git Bash / CMD），执行：

```bash
# 全局走 SOCKS5 代理（GitHub 等外网仓库）
git config --global http.proxy socks5://127.0.0.1:10808
git config --global https.proxy socks5://127.0.0.1:10808
```

### 6.3 国内仓库直连（推荐）

如果同时使用 gitee、coding 等国内仓库，不希望它们走代理，可以单独配置例外：

```bash
# gitee 直连
git config --global http.https://gitee.com.proxy ""
git config --global http.http://gitee.com.proxy ""

# coding 直连（如有需要）
git config --global http.https://coding.net.proxy ""
```

这样配置后：

- `github.com` → 走 v2rayN 代理 ✅
- `gitee.com` → 直连国内服务器 ✅

### 6.4 取消 Git 代理

如果不需要代理了，可以恢复：

```bash
git config --global --unset http.proxy
git config --global --unset https.proxy
```

### 6.5 查看当前 Git 代理配置

```bash
git config --global --get-regexp http
```

## 七、常用操作速查

| 操作 | 方法 |
| --- | --- |
| 切换节点 | 右键节点 → 「设为活动服务器」 |
| 测试节点延迟 | 选中节点 → 按 `Ctrl + T` 或点击 ⚡ 闪电图标 |
| 测试节点速度 | 选中节点 → 按 `Ctrl + R` 或点击 🔄 图标 |
| 更新订阅 | 「订阅分组」→「更新全部订阅」 |
| 关闭代理 | 右下角选择「清除系统代理」 |
| 查看日志 | 主界面下方即为实时日志区域 |

## 八、常见问题

**Q1: 更新订阅失败，节点列表为空**

- 检查订阅链接是否正确、是否过期
- 尝试选择「更新全部订阅（通过代理）」
- 确认网络连接正常

**Q2: 节点有延迟但打不开网站**

- 尝试切换其他节点
- 检查右下角是否为「自动配置系统代理」
- 重启 v2rayN 客户端

**Q3: 提示「配置项无效，请检查或重新选择」**

- 说明当前没有选中有效节点
- 更新订阅后，在列表中右键选择一个节点设为活动服务器

**Q4: 右下角显示「当前延迟: none」**

- 表示该节点无法连通
- 右键点击节点 →「测试服务器延迟」确认
- 换一个节点试试

**Q5: 日志提示 Shadowsocks 已弃用**

- 这只是警告，不影响使用
- 建议优先选择 VLESS 节点以获得更好的安全性和性能

**Q6: Git 拉取 gitee 代码报错 Failed to connect to 127.0.0.1 port 1080**

- 说明 git 配置了旧的代理端口（如 1080），与 v2rayN 实际端口不一致
- 按 **第六章** 重新配置 git 代理即可
- 或者为 gitee 单独设置直连：

  ```bash
  git config --global http.https://gitee.com.proxy ""
  ```

## 九、进阶设置（可选）

### 路由模式

右下角路由下拉框可选择：

- **绕过大陆 (Whitelist)：** 国内网站直连，国外网站走代理（推荐）
- **全局 (Global)：** 所有流量都走代理
- **直连 (Direct)：** 所有流量直连，不走代理

### 启用 TUN 模式

点击右下角的 **「启用 Tun」** 开关。

TUN 模式可以代理系统全局流量，包括不支持代理设置的软件。需要以管理员身份运行 v2rayN。
