## 一、项目启动：需求与排期

### 1.1 需求来源
需求可能来自多个渠道：
- **销售** 提出的客户需求
- **内部** 业务方的需求
- **现场** 问题反馈
- **下游公司** 的对接需求

### 1.2 评估与排期流程
```
需求 → 评估 → 立项 → 排期
```

### 1.3 团队角色与职责
作为项目负责人，你需要对以下人员**全部负责**：
- **售前**：技术方案预研、可行性评估
- **运维集成**：环境搭建、部署上线
- **测试**：功能验证、质量保证
- **上下游**：接口对接、联调协调

### 1.4 时间节奏
- **下班早** → **上班**（意味着工作节奏紧凑，需要高效推进）
- **1个月** 内要出**成果**，时间压力很大

---

## 二、技术调研与选型

### 2.1 调研流程
```
设计讨论 → 调研 → 调研完成
```

### 2.2 核心关注点
调研阶段需要确定：
- **组件/客户端/编写**：技术组件选择、客户端方案、编码规范
- **服务架构**：整体服务架构设计
- **业务理解**：深入理解业务需求，技术为业务服务

### 2.3 技术栈选型参考

#### 通信协议
| 类型 | 技术 | 适用场景 |
|------|------|----------|
| 第三方对接 | HTTP客户端 | 外部API调用 |
| 内部服务 | gRPC | 高性能内部通信 |

#### 数据库与ORM
- **DB**：数据库选型
- **JDBC**：Java数据库连接
- **MyBatis**：持久层框架

#### Web服务框架
- **API / WebAPI / REST API**：接口风格
- **Netty**：高性能网络框架
- **Tomcat**：传统Servlet容器

#### 统一处理层
- **异常**：全局异常处理
- **错误码**：统一错误码规范
- **过滤**：请求过滤、权限校验
- **拦截**：AOP拦截、日志记录

---

## 三、设计阶段

### 3.1 设计原则
- **API 切分**：合理划分接口粒度
- **统一**：保持设计一致性

### 3.2 沟通与理解
- **售前** 引导 → **同一业务理解** → **一致**
- 确保团队对业务语义理解一致，避免后期返工

### 3.3 核心设计文档
| 文档 | 内容 |
|------|------|
| **DB设计** | 数据库表结构、索引、关系设计 |
| **设计** | 整体架构设计文档 |
| **ERD** | 实体关系图 |

### 3.4 语义与规范
- **语义**：接口命名、字段含义要清晰明确
- **坑**：避免歧义，减少后期理解成本
- **体会**：积累经验，形成团队共识

---

## 四、开发阶段

### 4.1 开发原则
- **开发 → 不重复 → 库**：代码复用，封装公共库
- **一味开发 → 测试 → 方向**：避免盲目开发，通过测试验证方向

### 4.2 架构设计要点
- **结构**：清晰的模块划分
- **抽象**：提取公共逻辑
- **原子性**：最小功能单元
- **后期扩展**：预留扩展点，应对需求变更

### 4.3 协作与沟通
- **2个**：与上下游/上上级保持沟通
- **难**：独立负责时沟通成本高
- **多**：需要协调的关联方多

---

## 五、部署与运维

### 5.1 部署方式演进
```
部署 → 淘汰 → K8S/云
```
- 传统部署方式逐渐被淘汰
- 现代部署转向 **K8S** 和云平台

### 5.2 部署要素
| 要素 | 说明 |
|------|------|
| **组件** | 服务组件拆分 |
| **Endpoint** | 服务暴露端点 |
| **URL** | 访问路径 |
| **DB Table** | 数据库表 |
| **自己** | 自主维护 |
| **确认** | 部署前逐项确认 |

### 5.3 环境配置
- **脚本**：部署脚本自动化
- **库**：依赖库管理
- **文件**：配置文件管理
- **路径**：文件路径规范
- **配置**：环境配置分离
- **IP / Port**：网络地址管理
- **网络**：网络策略、安全组

#### 容器化工具
- **Docker**：容器化部署
- **Compose**：多容器编排

---

## 六、配置管理

### 6.1 配置分离原则
- **配置** 与 **代码/组件/网络** 分离
- **单独**：独立管理，不混在一起

### 6.2 配置传递
```
组件/网络 → 单独配置
```

### 6.3 启动参数
- **启动** 时传入 **参数**
- 通过启动参数实现环境差异化配置

---

## 七、联调与测试

### 7.1 联调流程
```
联调 → 细节修改
```

### 7.2 原因
- 设计阶段只能大方向比较稳，不要出现大的bug,联调阶段进行细节调整，事务的发展规律

### 7.3 评审与上线
- **评审**：代码评审、方案评审
- **向上级展示**：展示成果

---

## 八、独立负责项目的关键要点

### 8.1 全流程掌控
作为唯一后端负责人，需要覆盖完整链路：
```
需求 → 调研 → 设计 → 开发 → 测试 → 部署 → 运维
```

### 8.2 核心能力要求
1. **技术广度**：熟悉前后端联调、数据库、部署运维
2. **业务深度**：理解业务语义，技术方案贴合业务
3. **沟通协调能力**：对接售前、测试、上下游多方
4. **时间管理能力**：1个月内交付，节奏紧凑

### 8.3 避坑指南
- 避免"一味开发"，要边开发边验证
- 设计阶段确保团队"同一业务理解"
- 配置与代码分离，便于环境切换
- 提前考虑"后期扩展"，避免架构僵化
